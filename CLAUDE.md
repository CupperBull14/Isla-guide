# CLAUDE.md — правила проекта Isla Guide

Прочитай этот файл целиком ПЕРЕД любой правкой. Затем: `СТАТУС.md` (что сделано), `docs/ARCHITECTURE.md` (как устроено), `docs/DECISIONS.md` (почему так). Факты об игре — в `БАЗА_ЗНАНИЙ.md`.

## Что это
Фан-сайт-справочник по The Isle: **Evrima** (не Legacy), на русском. React 18 + TypeScript (strict) + Vite 5 + Tailwind 3.4 + Framer Motion 11 + React Router. Статический сайт (GitHub Pages / Vercel), без сервера. Не связан с The Isle Development / Afterthought LLC.

## Золотые правила данных (нарушать нельзя)
1. Игровые факты — только из проверенных источников (веб-поиск, официальные посты, EQG и т.п.), **никогда по памяти**.
2. **Не выдумывать числа и вердикты матчапов.** Нет данных → `null` / «данных нет».
3. Каждый значимый факт — источник + дата. Источник «проверено в игре опытным игроком» разрешён, помечается отдельно.
4. Только Evrima. Контент без привязки к Evrima отбрасывается.
5. Тексты — оригинальные (не копипаст вики и Dinotoria). Чужие цифры без проверки не переносим.
6. Непроверенное — ⚠️ и вопрос владельцу. Расхождения источников не «выбираем молча», а показываем.
7. Матчап читается строго «строка → столбец». Обратное направление **никогда не выводится** автоматически.

## Протокол изменений (как не ломать работающее)
1. **Сначала читай, потом пиши.** Открой файлы, которых коснёшься, и найди их использования (`grep -rn "имяСимвола" src`).
2. **Только аддитивно.** Добавляй новые файлы/поля/пропсы; существующие экспорты, поля данных и пропсы не удаляй и не переименовывай, пока `grep` не покажет ноль использований. Новое поле в типе — опциональное или с миграцией ВСЕХ файлов данных.
3. **Не переписывай с нуля** файл, который работает и не связан с задачей. Точечные правки (Edit), а не перезапись целого файла.
4. **Одна задача — один коммит.** Не смешивай фичу, рефакторинг и данные.
5. **Не трогай «замороженное» без явной просьбы владельца** — список ниже.
6. После правки: `npm run verify` (= `npm run check` + `npm run build`). Если `build` недоступен в окружении — минимум `npx tsc --noEmit -p tsconfig.app.json` и `npm run check`. Ошибки чинятся до коммита.
7. Обнови `СТАТУС.md`; если принято архитектурное решение — допиши ADR в `docs/DECISIONS.md`; новые факты — в `БАЗА_ЗНАНИЙ.md`.
8. `npm run dev` не запускать (держит владелец).

## Замороженное (менять только по прямой просьбе)
- Схема данных `src/types/index.ts`: существующие поля и их смысл.
- Семантика матчапов (строка → столбец) и шкала basis: `stated` / `derived` / `weak`.
- Формат источников: `{id,title,url,date,accessed}`; `url: ''` только для «проверено в игре».
- Принцип «контент только в `src/data/`, компоненты лишь рендерят».
- Правила анимаций (ниже).

## Правила кода
- TypeScript strict, **без `any`**; типы только из `src/types`.
- Контент не хардкодится в компонентах.
- Мобильная адаптивность обязательна (проверять брейкпоинты `sm/md/lg`), поля ввода ≥16px на мобильных.
- Доступность: `aria-*`, `scope` у таблиц, видимый фокус, `prefers-reduced-motion` (глобально через `MotionConfig`).
- **Анимации (ADR-004):** запрещён `AnimatePresence mode="wait"|"sync"` и exit-анимации для переключения вкладок/списков — это вызывало «зависание» (контент не появлялся, помогал только F5). Используй enter-only: `initial` + `animate` на элементе с `key`. Содержимое аккордеонов всегда в DOM, анимируется только высота. `layoutId` допустим только для «пилюль» активной вкладки.
- Тяжёлое — лениво: страницы через `lazyPage()`; при росте данных см. `docs/SCALING.md`.

## Работа с данными динозавров
Файлы `src/data/dinosaurs/*.ts` изначально сгенерированы скриптом, **теперь они — источник правды и правятся вручную**. Генератор не использовать (перезапишет ручные правки). Новый вид: скопируй ближайший файл-образец, добавь в `dinosaurs/index.ts`, прогони `npm run check`. Подробности — `docs/ARCHITECTURE.md`.

## Коммиты и git
- Автор — владелец проекта. **Строки `Co-Authored-By` / `Claude-Session` в коммиты не добавлять** (прямая просьба владельца).
- После git-операций в смонтированной папке чистить мусор: `find .git -name 'tmp_obj_*' -delete; rm -f .git/*.lock`.
- Формат: `Этап N: …` / `Данные: …` / `Фикс: …` / `Док: …` — по-русски, коротко.
- Историю уже опубликованного репозитория не переписывать без согласования (нужен force-push).

## Окружение (ограничения)
- В облачной среде нет доступа к npm-реестру и `vite build` (Windows-бинарники) — сборку запускает владелец; в среде работают `tsc` и `node scripts/check.mjs`.
- Большие heredoc в `device_bash` падают с E2BIG — режь файлы по ≤12 КБ.
- Владелец общается по-русски; ответ — кратко: что сделано / что проверить / что дальше.
